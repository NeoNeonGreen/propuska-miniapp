# Пропуска — демо Telegram Mini App

Демо-прототип приложения заказа пропусков на территорию посёлка.
Все данные — моки, интеграции (1С:ЖКХ, SIGUR, ЮKassa) имитируются на фронте.

## Состав

| Файл | Что это |
|---|---|
| `index.html` | **Готовая сборка.** Один файл, ничего собирать не нужно. React 18 (UMD с CDN) + Telegram WebApp SDK + скомпилированное приложение. |
| `PropuskaDemo.jsx` | Исходник (React-компонент). Нужен только если будете дорабатывать код. |

## Деплой (5 минут)

1. Положить `index.html` в корень сайта (или в подпапку) на любой хостинг.
2. Требования Telegram — оба обязательны, иначе Mini App не откроется:
   - **HTTPS с валидным сертификатом** (Let's Encrypt подойдёт);
   - **домен**, не голый IP.
3. Открыть URL в браузере и убедиться, что приложение работает.

Никакого бэкенда, БД и переменных окружения не нужно — это статичная страница.

## Подключение к Telegram-боту

1. В Telegram открыть **@BotFather** → `/newbot` → задать имя и username бота.
2. `/newapp` → выбрать бота → заполнить название, описание, загрузить иконку →
   указать **Web App URL** = адрес, где лежит `index.html`.
3. Готово: Mini App открывается по ссылке `https://t.me/<bot_username>/<app_short_name>`.

Дополнительно (по желанию):
- `/setmenubutton` в BotFather — чтобы приложение открывалось кнопкой меню в чате с ботом;
- кнопка в сообщении: `reply_markup` с `web_app: {url: "..."}` через Bot API.

## Поведение

- Внутри Telegram: вызываются `WebApp.ready() / expand()`, тёмные цвета шапки,
  кнопка «✕ Закрыть» закрывает Mini App (`WebApp.close()`).
- В обычном браузере: то же приложение, «Закрыть» возвращает на экран выбора роли.
  На широких экранах рендерится в центрированной «рамке телефона» (~400px).

## Что демонстрирует

- Роли: Собственник (K0), Член семьи (K1), Арендатор (K2), Ребёнок (K1.2) —
  выбор на стартовом экране, у каждой роли своё меню и права.
- Пропуска: разовый пешеходный/автомобильный, грузовой (депозит ≥ 1500 ₽,
  списание за пропуск, пополнение через мок-ЮKassa с успехом/ошибкой),
  временный, постоянный (через добавление пользователя).
- Согласование: заказы К1/2 и ребёнка уходят собственнику во вкладку
  «Запросы» (одобрить/отклонить), статусы видны в «Истории» заказчика.
- Коды пропусков по правилам ТЗ: разовые/временные начинаются с 1–7,
  грузовые с 8–9; копирование кода по тапу.
- Пользователи: лимит 5, тумблеры доступа, добавление по телефону и роли,
  двухшаговое удаление.
- Аккаунт: ФИО под замком, изменение ЛС/телефона через «согласование УК»
  (имитация ответа через ~4,5 сек, уведомление со статусом).
- Регистрация (демо): 3 шага, валидация полей, соглашения, имитация
  верификации в 1С:ЖКХ.

## Доработка исходника

`PropuskaDemo.jsx` — один самодостаточный компонент (стили внутри, зависимость
только `react`). Можно вставить в любой проект на Vite/Next/CRA:

```bash
npm create vite@latest propuska -- --template react
# скопировать PropuskaDemo.jsx в src/, отрендерить <PropuskaDemo/>
```

Точки для будущих интеграций собраны в корневом компоненте:
`placeOrder`, `placeCargo`, `decideRequest`, `paymentDone`, `addUser`,
`submitAccountEdit` — сейчас они меняют локальный стейт, при переходе на
реальный бэкенд заменяются на вызовы API. Авторизацию реального пользователя
делать через `window.Telegram.WebApp.initData` (проверка подписи на сервере).
